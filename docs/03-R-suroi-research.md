## 2. 자기장

### Suroi
반지름을 **맵 크기에 대한 비율**로 들고 있고, 한 단계를 **대기(Waiting) → 수축(Advancing)**
두 상태로 쪼갠다. 13개 항목이 그 둘을 번갈아 늘어놓은 구조다.

| 단계 | 반지름 비율 | 대기 | 수축 | DPS | 보급 |
| --- | --- | --- | --- | --- | --- |
| 0 | 0.76 | — | — | 0 | |
| 1 | 0.76 → 0.55 | 75s | 20s | 0 → 1 | |
| 2 | 0.55 → 0.43 | 45s | 20s | 1 | **투하** |
| 3 | 0.43 → 0.32 | 40s | 15s | 2 | |
| 4 | 0.32 → 0.20 | 35s | 15s | 3 | **투하** |
| 5 | 0.20 → 0.09 | 30s | 15s | 5 | |
| 6 | 0.09 → 0 | 20s | 60s | 10 | **투하** |

- **합계 약 390초 (6분 30초).** 마지막 수축만 60초로 길다 — 최종 원이 천천히 조여든다.
- **밖으로 깊이 들어갈수록 더 아프다**: `damageScaleFactor 0.005` / 깊이 `12` 유닛까지는 가산 없음.
- **보급 상자가 자기장 단계에 묶여 있다** (`summonAirdrop`) — 시계가 아니라 국면에 맞춰 떨어진다.
- `GAME_SPAWN_WINDOW = 84` — 84초 지나면 더 못 들어온다.
- 다음 원 중심을 정하는 방식은 `server/src/gas.ts` 가 들고 있고, 비율만 테이블에 있다.

### 우리는
우리 라스트 드롭(별개 완성품)은 6단계 288초, DPS 1.0→14 다. **구조를 세 군데 바꾸자고 제안한다.**

1. **반지름을 비율로 들자.** 지금은 절대값(310→200→…→6m)이라 맵 크기를 바꾸면 전부 틀어진다.
   01 문서가 데인 "맵 규모 바꾸면 옛 설정이 터진다"가 정확히 이 자리다.
2. **대기/수축을 분리해 테이블에 적자.** 우리는 `[대기, 수축, 다음반경]` 세 값을 쓰고 있어
   이미 비슷한데, 단계별 DPS 를 같은 줄에 두면 읽기 쉽다.
3. **깊이 비례 가산 피해를 넣자.** 지금은 밖이면 일정 DPS 라, 자기장 가장자리에서
   버티는 게 너무 싸다. Suroi 처럼 "일정 깊이까지는 그대로, 더 들어가면 가산"이 좋다.
4. **보급 상자를 시계가 아니라 자기장 단계에 묶자.** 우리는 95초·205초 고정인데,
   단계 2·4·6 수축 시작에 맞추면 "사람이 몰리는 때"와 겹쳐 교전이 생긴다.

### 읽히는 차이 넷

1. **우리 체감 TTK 가 2배 빠르다.**
   AK-47: 100 ÷ 14 = **8발 × 100ms = 0.7초**.
   우리 소총: 100 ÷ 28 = **4발 × 120ms = 0.36초**.
   16명 + 봇이 돌아다니는 판에서 0.36초면 **어디서 맞았는지도 모르고 죽는다.**
   → **제안: 소총 28 → 18, SMG 14 → 11, 권총 20 → 15.** 저격·샷건은 그대로 둔다
   (한 방 맞추는 재미가 그 둘의 성격이다).

2. **우리 퍼짐이 너무 좁다.** Suroi 는 도 단위로 2~18°, 우리는 0.1~3.4° 다.
   → 전체적으로 **2~3배 넓히자.** 특히 SMG·권총. 지금은 권총으로 50m 를 정밀 사격한다.

3. **이동 중 퍼짐이 우리에겐 없다.** Suroi 는 `moveSpread` 를 따로 들고 **걸으면 2~3배**로 벌린다.
   이게 "멈춰서 쏜다"를 만드는 장치다.
   → **제안: `moveSpread` 도입.** 우리는 자세(서기/앉기/엎드리기)가 있으니
   `퍼짐 × 자세배수 × (움직이는 중이면 2.4)` 로 곱해 쓰면 된다. **03+04 에서 제일 값싸게
   총질 맛을 바꾸는 한 수**라고 본다.

4. **장애물 관통 계수(`obstacleMultiplier`)가 있다.** 샷건은 나무·벽에 약하고 저격은 강하다.
   → 우리는 3D 라 벽이 완전 차폐다. **엄폐물 파괴를 안 넣을 거면 불필요하다.** 보류.

## 4. 방어구

### Suroi — **내구도가 없다.** 고정 비율 감소뿐이다.

| | Lv1 | Lv2 | Lv3 | Lv4 |
| --- | --- | --- | --- | --- |
| 헬멧 | 10% | 15% | 20% | 25% (특수 능력 붙음) |
| 방탄복 | 20% | 35% | 45% | 35% (대신 특수) |

### 우리는
라스트 드롭은 25/36/47% + **내구도 소모 후 파괴**다. 수치는 Suroi 방탄복과 거의 같다.

- **내구도를 넣을지는 판단이 필요하다.** 배그는 넣고 Suroi 는 안 넣는다.
  넣으면 "방탄복을 새로 주워야 한다"는 파밍 동기가 생기고, 안 넣으면 규칙이 단순하다.
- **헬멧과 방탄복 감소율 차이는 가져가자.** 머리는 어차피 ×2 배율이라
  헬멧 감소를 방탄복보다 낮게 두면 "헬멧 있어도 헤드샷은 아프다"가 유지된다.
  → **제안: 헬멧 12/18/24%, 방탄복 20/32/42%, 내구도 있음.**

## 5. 회복 · 아드레날린

### Suroi
**체력 회복과 아드레날린이 분리돼 있다.**

| 아이템 | 종류 | 양 | 사용 시간 |
| --- | --- | --- | --- |
| Gauze (거즈) | 체력 | 20 | 3s |
| Medikit | 체력 | 100 | 6s |
| Cola | **아드레날린** | 25 | 3s |
| Tablets | **아드레날린** | 50 | 4s |

- 아드레날린(최대 100)은 **지속 회복과 이동 속도**에 관여하는 별도 자원이다.
- **가방 레벨이 소지 한도를 정한다**: Lv0 거즈 5·메디킷 1 → Lv1 거즈 10·메디킷 2 → …

### 우리는
라스트 드롭은 붕대(+12, 상한 75) / 구급상자(+45, 상한 90) / 구급킷(100%) / 드링크(부스트).
**상한 체계는 배그 것이고 Suroi 와 다르다.** 어느 쪽이든 되지만 섞으면 헷갈린다.

- **가방 레벨 아이디어는 가져올 만하다.** 파밍에 "가방을 먼저 찾는다"는 단계가 생긴다.
  → **제안: 03 에 가방 3단계.** 없음 → Lv1 → Lv2 로 회복품·탄약 한도가 늘어난다.
- 상한 체계는 **배그식(붕대는 75까지만)을 유지**하자고 제안한다. 이미 그렇게 만들어 뒀고,
  "붕대로는 끝까지 못 올린다"가 구급킷의 가치를 만든다.

## 6. 인벤토리

### Suroi
**고정 4칸이다.** 타입이 칸마다 정해져 있다.

```
[0] 총   [1] 총   [2] 근접   [3] 투척
시작 활성 칸 = 2 (근접)
```
칸마다 잠금(lock) 상태를 비트마스크로 들고 있고, 줍기/버리기/교체가 전부 칸 단위다.

### 우리는
지금 총 2칸(`guns[0..1]`)만 있다. **구조가 같다** — 거기에 근접·투척 칸을 더하면 Suroi 와 같은 꼴이다.

- → **제안: 03 에서 4칸으로 확장.** `[총, 총, 근접, 투척]`.
  근접(주먹/삽)은 "총을 못 주웠을 때 할 게 있다"를 만들고, 투척(수류탄)은
  **3D 에서 건물 안을 공격하는 유일한 수단**이라 가치가 크다.
- 아이템 **버리기**가 우리에겐 없다. 칸이 4개가 되면 필요해진다 (`G` 키).

## 7. 파밍 · 전리품 테이블

### Suroi — **중첩 가중 테이블**이다
```
ground_loot : equipment 1 · healing 1 · ammo 1 · guns 0.9 · scopes 0.3
regular_crate: guns 1.25 · equipment 1 · healing 1 · ammo 0.5 · scopes 0.3 · throwables 0.3 · melee 0.04
```
테이블이 다시 테이블을 가리키고, 말단에 아이템이 가중치와 함께 놓인다.
건물 정의 안의 `lootSpawners` 가 **"이 건물의 이 좌표에 이 테이블을 깐다"**를 지정한다 (43개 건물).

**총 희귀도 분포**(지상 35종, 가중치 합 15.7):

| 흔함 | | 귀함 | |
| --- | --- | --- | --- |
| G19 | 12.7% | Dual Deagle | 0.01% |
| M1895 | 11.1% | Tango 51 | 0.01% |
| MPX | 10.8% | Negev | 0.02% |
| SAF-200 | 9.6% | VKS | 0.02% |

**최상위와 최하위가 2000:1 이다.** 저격은 거의 지상에 안 뜨고 보급 상자에서 나온다.

### 우리는
지금은 균등에 가깝다 (총 34% · 탄약 22% · 회복 24% · 헬멧 10% · 방탄복 10%, 총 종류는 균등).

- → **제안: 가중 테이블 도입.** 구조는 Suroi 와 같은 발상으로 하되 값은 우리가 정한다.
  ```
  건물 안 : 총 1.2 · 회복 1.0 · 방어구 0.9 · 탄약 0.6
  야외    : 탄약 1.0 · 회복 0.8 · 총 0.5 · 방어구 0.3
  보급상자: 저격·3레벨 장비 고정 (지금 그대로)
  ```
- → **총 희귀도를 벌리자.** 권총·SMG 는 흔하게, 저격은 지상에서 거의 안 나오게.
  지금은 저격을 5분 안에 주울 확률이 너무 높다.
- → **건물별 테이블**은 우리 건물이 한 종류뿐이라 아직 이르다. 건물 종류가 늘면 그때.

## 8. 봇 AI — Suroi 에는 없다

찾은 것은 `tests/src/stressTest.ts` 하나이고, 서버 부하를 재기 위해
가짜 클라이언트를 붙이는 코드다. **판단·교전 로직이 아니다.**

→ **우리 04 의 봇은 우리 것으로 짠다.** 가져올 자리는 **땅따먹기 25 문서**다:
성향 6종, 실력 공통(`BOT_SKILL`), 1% 실수, 자멸 방지 관문.
거기서 검증된 구조가 있으니 **총게임 버전으로 번역**하면 된다.

| 땅따먹기에서 | 배틀로얄에서 |
| --- | --- |
| 폐곡선 크기 | 교전 거리 선호 (근접형 / 중거리 / 저격형) |
| 사냥 비율 `aggr` | 교전 의지 — 보면 쫓나, 숨나 |
| 복귀 민감도 `flee` | 체력이 얼마 남으면 물러나나 |
| 아이템 우선도 | 파밍 성향 — 총만 먹나, 방어구까지 챙기나 |
| 자기장 대응 | 그대로 쓸 수 있다 (가장자리 판단 로직이 같다) |
| 1% 실수 | 그대로 — 조준 흔들림·재장전 타이밍 놓침 |

| | Suroi | 우리 |

| 승패 | `gameOverPacket` | 결과 화면에 등수·처치·명중률 |

→ **제안: 관전을 04 에 넣자.** 죽고 나서 "누가 이기나" 보는 게 배틀로얄의 절반이다.
봇전이면 구현도 싸다 — 카메라를 살아 있는 봇에 붙이고 좌우 키로 바꾸면 끝이다.

## 10. 서버 동기화 (우리 05 대비 — 참고만)

| | |
| --- | --- |
| 권위 | 서버 권위. **40 TPS** (`idealDt = 1000 / tps`) |
| 전송 | **바이너리 패킷 스트림** 13종 — `inputPacket`(클라→서버), `updatePacket`(서버→클라), `mapPacket`, `killPacket`, `gameOverPacket`, `spectatePacket`, `pickupPacket` … |
| 맵 | `mapPacket` 으로 한 번에 내려보낸다 (매번 안 보낸다) |
| 시야 | `buildingVisionSize: 20` — 건물 안은 보이는 범위를 줄인다 |
| 남용 방지 | `rateLimitInterval 1000` · `rateLimitPunishmentTrigger 10` · `combatLogTimeoutMs 12000` (교전 중 종료 패널티) |

우리 05 에 쓸 만한 것 셋.
1. **맵은 한 번만 보낸다.** 우리는 지형을 시드로 생성하니 **시드만 보내면 된다** — 더 싸다.
2. **입력만 올리고 결과만 받는다.** 땅따먹기에서 이미 host-authoritative 로 검증한 방식과 같다.
3. **교전 중 종료 패널티**(`combatLogTimeoutMs`) 는 온라인에서 필요해진다. 기록해 둔다.

## 11. 3D 로 옮길 때 달라지는 것

Suroi 는 2D 탑다운이다. 그 전제에서 온 설계는 우리에게 그대로 안 맞는다.

| 항목 | Suroi (2D) | 우리 (3D 1인칭) |
| --- | --- | --- |
| **시야** | 화면 안은 전부 보인다. 건물만 `buildingVisionSize` 로 가린다 | **등 뒤가 안 보인다.** 소리·피격 방향 표시가 훨씬 중요해진다 → **04 에 피격 방향 표시 넣자** |
| **엄폐** | 장애물에 겹치면 가려짐. 높이 개념 없음 | **고저차와 지붕이 엄폐다.** 01 에서 고저차 26.7m 를 넣은 이유 |
| **조준** | 마우스 방향으로 쏜다. 상하 없음 | **상하 조준·탄도**가 생긴다. 저격 300m 에서 낙차를 줄지는 판단 필요 |
| **퍼짐** | 각도 그대로 2D 원뿔 | 3D 원뿔. 지금 구현이 맞다 |
| **자세** | 없다 (엎드리기 개념 없음) | **앉기·엎드리기가 의미를 가진다** — 시야선과 히트박스가 같이 낮아진다 |
| **투척** | 포물선을 `projectiles.maxHeight 5` 로 흉내낸다 | 진짜 3D 포물선. 건물 **안으로** 던져 넣을 수 있다 → 가치가 더 크다 |
| **보급 상자** | 떨어질 때 맞으면 피해 300 | 3D 라 낙하 궤적이 보인다. **멀리서 보이는 연출**로 쓸 수 있다 |
| **맵 밀도** | 실제 교전 가능 1344유닛 / 플레이어 지름 4.5 = **약 300배** | 1000m / 0.9m = **약 1100배.** 우리 맵이 **상대적으로 3.7배 넓다** → 16명으로는 **사람을 못 만난다.** 자기장을 더 빨리 조이거나 맵을 줄이는 쪽을 봐야 한다 |

마지막 줄이 이번 조사에서 제일 중요한 발견이라고 본다. **우리 맵은 인원 대비 너무 넓다.**

## 12. 03 + 04 반영 제안 — 우선순위

| 순위 | 항목 | 근거 | 비용 |
| --- | --- | --- | --- |
| 1 | **이동 중 퍼짐 (`moveSpread`)** | 멈춰서 쏘는 맛. 자세 체계와 곱하면 끝 | 매우 낮음 |
| 2 | **무기 피해 하향** (소총 28→18 등) | 우리 TTK 가 Suroi 의 절반. 0.36초는 너무 빠르다 | 매우 낮음 |
| 3 | **맵 대비 인원 재검토** | 교전 가능 밀도가 Suroi 의 1/3.7 | 낮음 (상수) |
| 4 | **자기장 반지름을 비율로 + 깊이 가산 피해** | 맵 크기 바꿀 때 안 터진다. 가장자리 버티기 억제 | 낮음 |
| 5 | **가중 전리품 테이블 + 총 희귀도 분리** | 저격이 너무 흔하다 | 중간 |
| 6 | **인벤토리 4칸 (총·총·근접·투척) + 버리기** | 총 못 주웠을 때 할 게 생긴다. 수류탄은 3D 에서 특히 세다 | 중간 |
| 7 | **가방 3단계** | 파밍에 단계가 생긴다 | 중간 |
| 8 | **관전 (04)** | 죽고 나서 결말을 본다 | 중간 |
| 9 | **피격 방향 표시 (04)** | 3D 1인칭에서는 필수에 가깝다 | 낮음 |
| 10 | 봇 AI | **Suroi 에 없다.** 땅따먹기 25 문서를 번역해 온다 | 높음 (04 본체) |

**가져오지 않을 것**: 장애물 관통 계수(엄폐물 파괴를 안 하면 불필요) ·
아드레날린 분리 체계(배그식 상한 체계와 섞으면 헷갈린다) · 건물별 전리품 테이블(건물이 한 종류다).
