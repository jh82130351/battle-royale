# 01 - 3D 맵 + 컨트롤러

## 무엇을 했나
걸어다닐 수 있는 **1000×1000 맵 한 판**을 만들었다. 높이맵 지형, 건물 13채, 맵 경계,
1인칭 컨트롤러(WASD·Shift·Space·마우스), 시작 오버레이와 HUD.
배포 경로 `/game/br/` 도 뚫었다. **총·파밍·자기장은 02~04 단계다 — 지금은 이동만 된다.**

**텍스처 이미지는 한 장도 안 썼다.** 형태와 색으로만 만들었다.

---

## 1. 맵

| 항목 | 값 |
| --- | --- |
| 크기 | **1000 × 1000** (half 500) |
| 지형 격자 | 256 × 256 — 한 칸 3.9m |
| 고저차 | **26.7m** (최저 −9.7 · 최고 17.0) |
| 건물 | **13채** (1층 9 · 2층 4) |
| 콜라이더 | 104개 |
| 울타리 | ±494m |

### 완만한 언덕 — 산은 안 만들었다
FPS 쪽은 능선 노이즈로 산등성이를 세웠는데 **여기서는 뺐다.**
배틀로얄은 서로 보이고 쏠 수 있어야 하므로 시야를 끊는 큰 산을 두면 안 된다.
넓은 기복 + 군데군데 둔덕 + 잔굴곡, 세 겹만 포갰다.

경사 분포를 2만 군데 재 봤다.

| 경사 | 비율 |
| --- | --- |
| 0.0 ~ 0.2 (거의 평지) | 91.4% |
| 0.2 ~ 0.4 | 5.3% |
| 0.4 ~ 0.6 | 2.6% |
| 0.6 ~ 0.8 | 0.5% |
| **0.8 이상 (미끄러짐)** | **0.3%** |

걷는 데 지장 있는 면이 0.3% 뿐이다. "완만한 언덕"에 맞다고 본다.
다만 **엄폐가 되려면 고저차가 더 필요할 수도 있다** — 처음엔 20m 였는데
들판이 너무 밋밋해서 26.7m 로 올렸다. 더 올릴지는 만져 보시고 알려 주시면 좋겠다.

### 건물
자리는 좌표 해시로 정한다 — **누가 접속하든 같은 자리에 선다**(05 온라인에서 중요해진다).
중앙 랜드마크 1채 + 반경 140m 링 + 반경 300m 링. 시작점 55m 안에는 안 짓는다.

폭 14~28m · 깊이 11~22m · 1층 또는 2층 · 조금씩 틀어 놓았다(다 반듯하면 바둑판처럼 보인다).
벽·문·창·지붕·옥상 난간이 있고, **문으로 들어가 안을 지나 뒤쪽까지 갈 수 있다.**
**03 파밍 단계에서 이 13곳이 전리품 스폰 지점이 된다.**

### 경계
보이지 않는 벽에 부딪히면 버그처럼 느껴진다. **보이는 울타리**를 세웠다 —
25m 간격 기둥 + 지형을 따라 오르내리는 반투명 판. 물리는 좌표를 직접 자른다
(콜라이더로 하면 1km 짜리 상자가 되어 충돌 루프가 느려진다).

## 2. 컨트롤러
FPS Builder 것을 가져왔다. 편집 모드·벽타기·백플립·수영은 **다 떼어 냈다.**

| 키 | 동작 |
| --- | --- |
| WASD | 이동 (걷기 6.2 m/s) |
| Shift | 달리기 (10.5 m/s) |
| Space | 점프 |
| 마우스 | 시점 (Pointer Lock) |
| Esc | 잠금 해제 — 화면을 다시 클릭하면 잡힌다 |

- **시작 오버레이**를 클릭해야 Pointer Lock 이 걸린다. 브라우저가 사용자 제스처를 요구한다.
- 잠금이 풀리면 **누른 키를 전부 놓는다.** 안 그러면 Esc 를 누른 순간의 방향으로 계속 걷는다.
- 창을 벗어날 때(`blur`)도 같다.

## 3. 검증

### 맵 끝까지 걸어가기 — 네 방향 전부
```
북  493.6 / 경계 493.6   넘음 없음   발밑오차 0.000
남  493.6 / 경계 493.6   넘음 없음   발밑오차 0.010
동  493.6 / 경계 493.6   넘음 없음   발밑오차 0.000
서  493.6 / 경계 493.6   넘음 없음   발밑오차 0.000
```
'발밑오차' 는 **땅을 딛고 있을 때 발바닥과 지면 높이의 차이**다. 0 이면 정확히 붙어 있다는 뜻이다.
(FPS에서 나무가 떠 보였던 게 이 값이 안 맞아서였다.)

### 언덕 오르내림
경사 0.22 이상인 자리를 골라 오르막으로 2.5초씩 걸었다.
```
시도 5곳 · 실제로 올라감 5곳 · 최대 발밑오차 0.000
```

### 건물 충돌
벽 콜라이더마다 네 면 바깥에 붙여 놓고 0.8초씩 밀어붙였다.
```
시험 260회 · 뚫림 0 · 최대 침투 0.000
```

### 문 출입
```
들어감 13 / 13 · 다시 나옴 13 / 13
```

### 콜라이더가 실제 벽과 겹치나
```
표본 2,175 · 일치 2,175 · 어긋남 0 · 100%
```

### 지형
```
2만 군데 표본 — NaN 0건 · 최저 -9.7m · 최고 17.0m
```

## 4. 만들다 잡은 버그 셋

### (1) 문으로 들어갈 수 없었다
건물 바닥판(두께 0.24m)에 콜라이더를 걸었더니 **그게 벽처럼 막았다.**
수평 충돌이 "발보다 위에 있는 상자면 막는다"로만 돼 있어서, 24cm 턱도 벽이 된다.

**계단 오름(step-up)** 을 넣었다. 발끝에서 0.55m 이내의 턱은 수평으로 안 막고,
수직 판정에서 같은 여유로 올려 준다. **두 여유가 같아야** '안 막히는데 올라가지도 못하는' 틈이 안 생긴다.

### (2) 콜라이더가 건물과 반대로 돌아가 있었다 — 제일 위험했던 것
메시는 three.js 쿼터니언으로 놓고, 충돌은 FPS 코드의 회전식을 그대로 가져왔다.
**그 둘의 부호가 반대다.**

three 의 Y축 회전은
```
월드 = ( lx·cos + lz·sin , −lx·sin + lz·cos )
```
인데 FPS 충돌 코드는 반대 부호 식을 쓴다. FPS에서는 메시도 같은 식으로 놓아서 아귀가 맞았다.
여기서는 **중심은 맞는데 상자만 반대로 돌아갔다** — 회전된 건물에서
벽 없는 곳이 막히고 벽이 뚫린다.

`toLocal` / `toWorld` 두 함수로 변환을 한곳에 모으고 부호를 three 기준으로 맞췄다.

> **이걸 처음 검사에서는 못 잡았다.** "벽을 향해 걸어가 뚫리나"만 봤는데,
> 그 검사는 콜라이더끼리만 비교하므로 **메시와 어긋난 건 안 보인다.**
> 눈에 보이는 벽 위치를 직접 뽑아 콜라이더와 대조하고 나서야 드러났다(일치율 0%).

### (3) 창이 벽 속에 파묻혀 안 보였다
벽 두께가 0.5라 겉면이 중심에서 0.25 떨어져 있는데, 창을 0.08 에 뒀다.
**벽 안에 완전히 들어가** 화면에 창 없는 민무늬 건물이 나왔다.
겉면 바깥으로 빼고 창틀을 둘러 고쳤다.

## 5. 성능

| 보는 곳 | 드로우콜 | 삼각형 |
| --- | --- | --- |
| 시작점 | 46 | 66,050 |
| 건물 앞 | 46 | 69,146 |
| 탁 트인 들판 | 33 | 46,250 |
| 맵 끝 | 23 | 29,314 |

지형을 **8×8 = 64장 타일**로 쪼갰다. 메시 하나로 두면 경계구가 맵 전체를 덮어
프러스텀 컬링이 안 듣고, 어디를 보든 13만 삼각형을 통째로 올린다.
건물은 한 채가 **메시 하나**다 (조각 수십 개를 하나의 지오메트리로 합치고 색은 버텍스 컬러).

> **실기 fps 는 이번에도 못 쟀다.** 서버가 소프트웨어 렌더라 GPU 수치가 안 나오고
> 헤드리스에서는 가상 시간 때문에 프레임 간격이 뭉개진다(스크린샷의 fps 2 는 그래서다).
> 드로우콜·삼각형으로 대신 적는다. **실기 확인은 정현님께 부탁드린다.**

## 11. 감독 확인 요청 사항

1. **걸어 보시고 맵 크기가 맞는지.** 1000×1000 을 끝에서 끝까지 달리면 약 95초다.
   8인이면 적당하다고 보는데 체감이 중요하다.
2. **고저차 26.7m 가 충분한지.** 엄폐가 되는지, 아니면 더 울퉁불퉁해야 하는지.
3. **건물 13채가 적당한지.** 03 파밍에서 이 자리들이 전리품 지점이 된다.
   더 필요하면 지금 늘리는 게 싸다.
4. **달리기 10.5 m/s 가 빠른지 느린지.** 배틀로얄은 이동 시간이 길어서 체감이 갈린다.
5. **실기 fps** (5번).
